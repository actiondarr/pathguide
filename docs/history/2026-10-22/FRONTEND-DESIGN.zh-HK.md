# 領路通 PathGuide 前端與裝置端方案

文件日期：2026 年 10 月 22 日

本文件專門說明使用者如何操作 App，以及手機端的畫面、讀屏、相機、候選影像擷取與扶手電梯方向分析。此處「前端」包含 Flutter 介面及 iOS／Android 原生相機與推理模組。

目前只有九類裝置端物件辨識、相關介面及播報已實作。下列任務首頁、主動開始／暫停、照片收集、明暗主題與扶手電梯方向分析均屬後續設計，尚未實作或驗證。

配套文件：[Dataset 與模型訓練方案](../../DATASET-TRAINING.zh-HK.md)、[後端方案](../../BACKEND-DESIGN.zh-HK.md)，以及 [帳號註冊與個人模型流程](../../ACCOUNT-REGISTRATION.zh-HK.md)。完整的讀屏規則、導航及菜單文字線框，保留於 [無障礙研究與操作設計](../../ACCESSIBILITY-RESEARCH.zh-HK.md)。

下一版辨識依 Dataset 方案規劃為主物件偵測、按需牌內多圖示偵測及離線 OCR；20 類候選與樓梯合併不代表目前模型已更新。原先 18 類經清單審核後補入道路車輛及固定細柱，兩者仍需資料及真機驗證，亦不由框直接推斷車速、距離或碰撞危險。牌面查詢須有可讀屏的明確操作及結果狀態，依原始解析度影像分析，不因查詢而開啟收集。圖示、文字與箭嘴配對不清楚時只讀出可確認內容；樓梯方向屬性及扶手電梯運行方向均不能由主模型類別直接推斷。類別及資料規則以 Dataset 文件為準。

## 1. 使用者操作與無障礙介面

首頁依次提供「即時辨識」「路線導航」「讀取菜單」「設定與使用教學」，尚未提供的功能在名稱及讀屏狀態中標示「開發中」。教學可跳過及重播，相機、定位與錄音均在相應任務需要時才解釋及申請。

主要操作至少 56 × 56 Flutter 邏輯像素；頁面依「標題、狀態、操作、結果、其他設定」朗讀，面板關閉後返回原焦點。保留大字體、明暗主題及視覺預覽，所有核心操作亦能以讀屏按鈕完成。

讀屏開啟且沒有已儲存偏好時，預設按需讀取環境結果；連續播報由使用者啟用。介面朗讀與物件語音經統一調度，避免同一句重複發聲。設定、錄音及方向分析時，暫停普通物件的自動播報；過期結果不排隊補讀。

基本離線辨識可使用內置模型，毋須登入。開啟照片收集、上傳或存取個人模型前，以手機短訊驗證碼註冊／登入；註冊後收集仍預設關閉，所有資料以 Firebase UID 綁定。首次登入只顯示使用基礎模型，不假稱已產生個人權重。

即時辨識主畫面固定提供「暫停／繼續」「讀取目前結果」「自動播報」及「返回」。狀態區分尚未開始、準備中、辨識中、已暫停及暫時不可用；無結果與相機／模型失敗不能使用同一提示。

導航以目的地覆核、開始、重播下一步及結束為主要操作；菜單先提供類別，再讓使用者搜尋、重讀或重拍。兩者尚未接入服務，不能用模擬資料冒充真實結果，詳細線框見無障礙文件。

## 2. 候選照片擷取

### 2.1 觸發條件與原生相機

現有模型只能在已訓練的九類中輸出類別、框及分數。未知物件可能沒有框，也可能被高信心誤認為已知類別；低信心不等於未知物件，沒有框亦可能只是背景。因此收集的是「待覆核候選影像」，不能聲稱自動發現所有新類別。

| 來源 | 收集方法 | 覆核重點 |
|---|---|---|
| 低信心候選 | 同區域低信心框持續出現後擷取一張 | 已知類別困難樣本、誤認及可能新物件 |
| 少量場景抽樣 | 不論是否有框，抽取不同場景並去重 | 模型完全忽略或高信心誤認的物件 |
| 手動回報 | 按「回報辨識問題」擷取 | 補充自動策略漏掉的情況 |

初始可調參數沿用已討論的方案：低信心範圍 `0.20–0.60`、同區域持續約一秒；場景抽樣最多每分鐘一張及每日十張；自動擷取合計每日最多五十張，兩次至少相隔三十秒。這些是實驗起點，須用候選有效率、重複率及手機效能校準，不能當作已驗證的最佳值。

現有原生解碼會先按顯示門檻過濾結果，需另保留收集候選，不能只根據 Flutter 已收到的框判斷。候選框與擷取影像須來自同一幀；保存轉正後、沒有介面或畫框的 JPEG，不能用 App 截圖。品質檢查、去重與編碼不得阻塞 UI 或即時推理。

### 2.2 同意與本機待傳管理

「協助建立我的個人模型」預設關閉，先登入並另外同意，與使用相機的系統權限分開。使用者開啟前，先以可讀及可聽的方式解釋會擷取環境照片、Wi-Fi 上傳、個人微調用途、獲授權覆核人員及保留設定；拒絕不影響辨識。只在即時辨識任務運作時自動擷取，暫停、離開或鎖屏即停止。

照片在擷取時綁定目前 UID，待傳佇列按 UID 分隔；登出會停止工作並清除本機待傳及私人模型快取，雲端資料需另外處理。待傳照片可因重試而上傳多次，但固定使用同一識別碼，伺服器不得建立重複樣本。一般設定提供目前收集狀態、待傳數量、「暫停收集」與「清除待傳照片」。關閉收集後同時停止新擷取與待傳上傳，重新開啟後才恢復；清除待傳項目不代表已刪除雲端或訓練資料。

手機待傳容量上限為五十張或 50 MB，照片七日到期清除；滿額停止新增而不影響辨識。預設等 Wi-Fi，照片去除 EXIF、不附 GPS。雲端保存與覆核狀態由後端方案管理；本機清除操作只處理待傳項目。

這些數值是設計起點，尚未有本專案手機效能或候選有效率實測。回報按鈕可以略過自動擷取的冷卻，但仍受容量限制。未開啟收集、沒有網絡或待傳已滿，均不得阻止即時辨識。

## 3. 扶手電梯方向分析

### 3.1 現場支援與使用方式

港鐵資料指出，扶手電梯發聲提示器用來協助乘客辨別位置及運行方向；西九龍站的無障礙介紹亦列出相關設施。不能由此推定所有商場都有相同聲音，亦不能把聲源固定在左或右、某種聲音頻率直接當作所有地點通用的上落規則。[港鐵關愛乘客資料](https://www.mtr.com.hk/archive/en/services/caring_for_our_customer_booklet.pdf)、[高速鐵路無障礙乘車](https://www.highspeed.mtr.com.hk/tc/guide/accessibility.html)

領路通的查詢流程須保留聆聽現場聲音的空間，與使用者既有定向行動技能及場地協助並用。機電署要求乘搭前辨明方向，並指出不要在出入口逗留、出入時不要使用手機。因此 App 不應叫使用者站到踏板邊、伸手試帶或踏上去測方向；應在不阻塞通道及遠離出入口的位置先完成查詢，需要時尋求職員協助。[機電署鐵路扶手電梯指引](https://www.emsd.gov.hk/railway_city/tc/safety2.html)、[機電署安全使用自動梯守則](https://www.emsd.gov.hk/tc/lifts_and_escalators_safety/responsible_persons_corner/safe_use_of_lifts_escalators/index.html)

### 3.2 物件、入口與運行方向

| 問題 | 所需證據 | 單靠目前模型能否回答 |
|---|---|---|
| 畫面中是否有扶手電梯 | 物件框及類別 | 可提出辨識結果，仍可能誤檢 |
| 畫面這一端是否顯示准入／禁止進入 | 與同一部扶手電梯綁定的燈號或標誌 | 不可以，需要新標誌辨識 |
| 扶手電梯實際往較高／較低樓層移動 | 上下端位置、相對移動及必要交叉證據 | 不可以，需要時間序列分析 |

畫面中向上的箭嘴可能表達進入或通行方向，不能直接換成「往較高樓層」。即使辨認到准入標誌，也只描述標誌，不能保證踏板、空間或進入時機安全。同樣，地圖記載的方向、外形朝上、扶手帶的單張影像或正在步行的乘客，均不能單獨證明實際運行方向。

目前 `escalator` 使用專案 ID 49，`upstairs`／`downstairs` 是樓梯類別。方向是同一設備的動態屬性，不更改現有物件 ID，也不以樓梯分類代替扶手電梯方向。

### 3.3 裝置端分析流程

採用「物件定位 → 同一實例追蹤 → 標誌與上下端判斷 → 短時運動分析 → 結果檢查」的研究原型，先在受控資料驗證，尚未有可供使用者依賴的準確率證據。

1. 用現有模型找到扶手電梯，追蹤同一實例。若多部相鄰設備未能可靠分開，不猜哪一部較接近或位於使用者哪個方向。
2. 在同一實例找梯級、固定結構、上／下端及相關入口標誌；標誌不能跨配到旁邊另一部。幾何判斷須結合校正後視角及重力方向，畫面上半部不等於物理較高樓層。
3. 使用原生相機約三秒的連續影像作初始觀察窗口，不沿用低頻候選照片抽樣。以固定背景估計並補償手機移動，再分析梯級區域的相對光流，排除乘客及反射，扶手帶只作輔助。
4. 將相對移動與已確認的上／下端結合，再與入口證據比較。晃動、遮擋、取樣不足、方向衝突、目標切換或觀察逾時均回傳「未能判斷」。只有多幀一致及通過獨立驗證的結果才可輸出方向資訊。

光流描述的是相鄰影像的表觀位移，可能來自物件或相機本身；因此不能只看畫面向上／向下的位移。OpenCV 提供光流的基本方法，但沒有保證特定扶手電梯場景可靠。[OpenCV 光流說明](https://docs.opencv.org/4.x/d4/dee/tutorial_optical_flow.html)

相關 2025 年預印本亦討論扶手電梯動態理解及稀疏影格的限制，提出運動與語意分流的研究方向；它不是本專案演算法已獲驗證的證據。[The Escalator Problem](https://arxiv.org/abs/2508.07989)

以下是幾何關係示例，只適用於已確認同一部設備及所在端點，不能用來替代實際估計：

| 觀察端 | 梯級相對此端移動 | 可推導的實際方向 |
|---|---|---|
| 下端 | 從此端離開，沿梯身移動 | 向上 |
| 下端 | 沿梯身朝此端移動 | 向下 |
| 上端 | 從此端離開，沿梯身移動 | 向下 |
| 上端 | 沿梯身朝此端移動 | 向上 |
| 端點或運動不明 | 任意 | 未能判斷 |

「朝此端移動」描述梯級沿梯身的流向，不是看梯級在手機畫面中的垂直像素正負值；亦不代表該端可進入。沒有可靠運動訊號時，記錄為「未觀察到可靠移動」，不要直接斷言已停機。

### 3.4 操作與粵語回饋

探索頁在偵測到扶手電梯後，可提供「查詢扶手電梯方向」；仍未實作時標示「開發中」。不在每次出框時自動開始或反覆播報。方向分析在本機進行，不等待雲端回答。

```text
扶手電梯方向                                頁面標題
尚未開始／分析中／未能判斷                    任務狀態
[開始分析]                                  只在未分析時可用
[重讀結果] [重新分析]
[停止分析並聆聽現場] [返回探索]

目標：同一部扶手電梯／目標未能確定
運行方向：向上／向下／未能判斷
入口標誌：辨認到的內容／未能辨認
結果只描述最近觀察，不是進入指令
```

操作順序為：取得安全位置及持機說明 → 使用者明確開始 → 暫停普通物件播報、以短提示告知分析中 → 一次讀出結果或原因 → 可重讀、重試或停止。VoiceOver 與結果語音不重疊；「停止分析並聆聽現場」取消待播語音及分析，保留可操作介面。

| 情況 | 粵語例句 |
|---|---|
| 只有物件結果 | 「辨認到扶手電梯，暫時未能判斷上落方向。」 |
| 通過驗證的方向結果 | 「根據剛才畫面，呢部扶手電梯向上運行。」或「向下運行。」 |
| 只辨認到標誌 | 「辨認到禁止進入標誌；未能確認上落方向。」 |
| 多部設備或證據衝突 | 「未能確認係邊部扶手電梯，方向未能判斷。」 |
| 畫面不穩或影像不足 | 「畫面未夠穩定，方向未能判斷。可以重新分析，或請職員協助。」 |

方向結果須有觀察時間及目標識別；目標丟失、切換、觀察失效或任務結束時清除，重讀不能把舊結果說成現在仍然有效。未知時不預設向上或向下，不說「可以踏上去」「右邊嗰部安全」或用模型分數當安全保證。

方向查詢的連續影像只在記憶體處理，完成後釋放，預設不錄影、不上傳；照片收集同意不涵蓋影片。方向研究資料由 Dataset 方案另外管理，不讓使用者在出入口附近為研究補拍或試乘。

## 4. 與 Dataset 及後端的交接

| 輸出或依賴 | 前端責任 | 交接對象 |
|---|---|---|
| 候選照片 | 取得同一幀的轉正 JPEG、候選框與分數，記錄模型版本及觸發原因 | 後端上傳與記錄 |
| 上傳進度 | 顯示待傳、重試及已上傳，不把上傳成功說成已學會 | 後端狀態 |
| 模型與標籤 | 載入相符的 TFLite、清單及中文標籤，拒絕不一致映射 | Dataset 發佈包 |
| 方向結果 | 只輸出目前目標的有效觀察，未知及失效時清除方向 | 本機方向模組 |
| 訓練資料 | 不把預測直接當真實標註，不在手機自行訓練 | Dataset 人工覆核與批次訓練 |

前端不得包含 Firebase 管理員憑證或訓練服務密鑰。共用基礎模型隨 App 提供；個人模型在後端核准後，由本人選擇「下載並使用」。下載與切換需核對 UID、雜湊、清單及類別相容性，失敗保留基礎／舊模型；不在背景自動切換。此規格取代先前所有模型只隨 App 發佈的設計，詳細生命週期見帳號文件。

## 5. 前端驗收與實作起點

- [ ] VoiceOver／TalkBack 可完成開始、讀取、暫停、設定及返回，焦點不被辨識更新搶走。
- [ ] 面板有明確關閉操作，主要按鈕在大字體、不同主題及小螢幕仍可操作。
- [ ] 相機拒絕、語音失敗、來電、背景及鎖屏後均有可理解狀態；返回前台需明確繼續。
- [ ] 關閉收集、未同意、模擬資料及鎖屏不擷取；同一幀對應、去重、冷卻與容量限制正確。
- [ ] 斷網及上傳失敗不影響辨識，重試沿用相同照片識別與工作狀態。
- [ ] 登出／切換帳號會取消舊工作，A 的待傳照片、模型快取及延遲回應不能轉到 B；無個人模型時使用內置版本。
- [ ] 普通物件語音、介面朗讀及方向結果不重疊，停止操作會取消待播語音。

方向原型至少包含以下測試，全部先用有正確答案的受控短片，不讓使用者靠未驗證原型進入運行中的扶手電梯：

- 上行／下行各自從上端及下端觀察，並加入斜角、手機轉動及重力方向變化。
- 同一部設備在不同時段改變方向；相鄰兩部反向運行及目標交叉。
- 靜止、慢速、啟停、低光、強反光、燈號閃爍、重複梯級及抽幀造成的錯覺。
- 有／沒有／看不清入口標誌，以及標誌、幾何與運動證據不一致。
- 乘客步行、擁擠遮擋、手機晃動、掉幀、目標離開畫面及分析逾時。
- VoiceOver 開啟與 Screen Curtain 下的開始、停止、重讀、未知及失效結果；普通播報不能蓋過現場提示。

方向正確率、錯報率與拒答覆蓋的評估方法見 Dataset 方案。功能正式開放前須與視障使用者及定向行動專業人士共同驗證，不能把文件或有限受控測試當成安全證明。
