## App定位

領路通是一個以香港視障人士為主要服務對象的手機輔助App，將相機、文字、位置及距離資訊轉成粵語或英文提示，協助使用者了解環境、尋找目的地、閱讀日常資訊及處理出行任務。設計以簡單操作、讀屏支援和可隨時停止為核心，配合使用者原有的定向工具使用。

## 整體使用流程

- **出行：** 說出目的地 → 確認路線 → 接收步行及環境提示 → 到達附近後確認入口；進入有地圖的場地後接續室內路標導航。
- **了解眼前環境：** 開始協助 → 聽取重點 → 問物件、文字或距離 → 資訊不清時重新掃描 → 隨時暫停或退出。
- **用餐：** 拍攝菜單 → 瀏覽分類 → 問菜名或價格 → 聽取可確認結果，需要時重拍。
- **改善體驗：** 自願回報問題 → 覆核及修正 → 獨立比較 → 接收合格更新；不合適時回退。

本文件只介紹完整產品目標。實作、品質與驗收的詳細依據分別由[Frontend](FRONTEND-DESIGN.zh-HK.md)、[Backend](BACKEND-DESIGN.zh-HK.md)及[Dataset Review](DATASET-REVIEW.zh-HK.md)維護。

## 操作及資料原則

主流程保持固定控制；日常設定與進階／測試內容分開。每個按鈕可由VoiceOver描述用途及狀態，操作後提供必要結果回饋，避免系統讀屏與App重複播音；標準操作及大字先完成，再提供選填快捷手勢。陌生室內缺少可信方向線索時，提供掃描、暫停或求助，保持位置／方向未知。

按「開始協助」後進入基本環境觀察及簡短語音；透過「問一下」表達任務，App按需要選能力。保留暫停、重讀、結束及文字／按鈕替代。基本辨識及已錄室內路線重行以本機運作，複雜看圖問答可另經同意選用雲端；分析、回報及訓練分開授權。

室內有三個不同概念：**探索**是依現場線索找下一段；**錄製**是保存實際行過的路；**重行**是利用已保存或已核對的資料導航。首次到訪也可以錄新路；沒有方向資料時，錄製本身不會產生目的地位置。

<a id="route-landmark-learning"></a>
已錄路線可選擇參與持續改善：啟用後保留有限且有用的候選畫面，由開發者或測試員行程後核實，減少沿途操作。已核實觀察可補強本機路標記憶；另行同意的必要資料可作私人路標模型批次訓練，以另一趟行程比較，通過才提供可回退更新。補記憶與更新模型分開顯示，不要求每次全量上傳或訓練，也不保證每版更準；普通重行仍不額外保存影像。

## 目標功能

| 功能 | 使用者可以做甚麼 |
|---|---|
| 簡潔首頁與自動功能調度 | 按「開始協助」進入，透過「問一下」、重讀、暫停及繼續操作；App按任務調用辨識、文字、測距或導航，毋須自行選模型 |
| 即時物件辨識 | 了解眼前的行人、車輛、垃圾桶、柱、雪糕筒、樓梯、扶手電梯、圍欄、門及其他納入模型的物件與設施 |
| 語音及場景摘要 | 以粵語或英文聽取目前環境重點、物件位置及可確認資訊；可重播，避免多項功能同時搶播 |
| 看圖及場景問答 | 按「描述前方」取一張相，聽取兩至三句繁體廣東話；經明示選用Qwen雲端分析可見前方物件與畫面左中右，無法確認時明示不確定，可取消；自動描述為另可開關的目標 |
| 物件與距離 | 在硬件支援時了解物件相對位置及估算表面距離；量不到時提供重新對準、站定或退出等下一步 |
| 室內空間畫面 | 以鳥瞰示意呈現使用者、物件、障礙、地面及未知區，配合語音理解周邊空間 |
| 近距離行進協助 | 在已確認的眼前範圍提供短路徑及左右方向提示；遇到轉角、遮擋或觀測失效時提示停下重新掃描 |
| 懸空及近身障礙提醒 | 在感測可靠時提示通行範圍內的障礙，包括身體或頭部高度的物件 |
| 戶外步行導航 | 從「搜尋目的地／我的路線／錄製新路線」進入；搜尋及最近目的地→地圖、距離與預計時間預覽→開始步行、重讀、暫停／繼續及偏離重算。可收藏地點，保存GPS軌跡及路標；不納入大眾運輸或叫車串接 |
| 導航中環境辨識 | 在路線提示之間接收環境資訊，讓轉彎指示、物件播報及使用者查詢有一致的優先次序 |
| 室內目的地與跨樓層導航 | 利用已錄路線或已建立及核對的場地資料，以路標確認位置，尋找課室、店舖或設施，並利用樓梯／電梯連接樓層 |
| 陌生室內逐段探索 | 沒有路線或場地圖時，按現場指示牌、文字與使用者確認逐段了解方向；有依據才提出下一段候選，不預先聲稱知道整條路，可在同意後同步錄路 |
| 路線錄製與路標管理 | 主動記錄常用路線與路標，之後回放、重走及修正；場地改動可更新相關內容 |
| 指示牌理解 | 拍攝指示牌，結合圖示、文字與箭嘴，了解設施名稱及對應方向；配對不清時可重拍 |
| 菜單閱讀與查價 | 拍攝菜單、瀏覽分類，以文字或粵語查詢菜名與價格；多個價格或配對不清時保留說明 |
| 扶手電梯及門的資訊 | 根據連續觀察、標示及文字，提供可確認的扶手電梯方向或門推拉資訊，不靠單一外觀猜測 |
| 路口資訊 | 辨識相關行人燈、燈號及斑馬線，描述可確認的觀測；不把一次辨識當成可以過路的指令 |
| 電梯樓層資訊 | 讀取顯示器或按鈕上的樓層文字及可確認狀態，協助使用者理解電梯資訊 |
| 空間音效 | 在方位與距離可靠時，以不同方向的提示音輔助理解物件位置，並與讀屏及語音協調 |
| 耳機手勢與鎖屏語音 | 支援相容耳機的選填頭部手勢，以及經平台驗證的鎖屏路線語音；保留明確按鈕作替代，鎖屏時相機能力另行處理 |
| 無障礙與個人設定 | 支援VoiceOver／TalkBack、大字、繁體中文／英文、語速及播報設定，並配合標準鍵盤、點字及適用的系統捷徑 |
| 帳號及緊急聯絡 | 登入、管理及刪除帳號，保存選填聯絡人；使用者主動操作後交由系統撥號。其他登入方式透過帳號連結管理 |
| 問題回報與持續改善 | 經同意回報認錯、漏認、距離不對或文字配錯；經覆核後用於改善，使用者可了解處理狀態及撤回相關同意 |
| 共用／私人模型更新 | 比較共用改善與個人資料微調的效益；合格才提供更新，顯示改動與限制，效果變差時可回上一版本 |
| 跨平台與能力調整 | 支援iPhone及Android，按感測器、系統與服務提供合適功能；沒有可靠深度或相關能力時，清楚顯示限制 |

室內已知路線導航依賴已錄路線或已核對的場地資料；陌生場地探索是另一項完整產品目標，資訊不足時不能承諾找到目的地。近距離引導只使用有效觀測，不把「沒有辨識框」當作前方暢通。這些界線亦是完整產品的操作原則。

## 主要工具及選用原因

基本版以普通相機提供物件名稱、畫面左／中／右及本機路標重認，不要求ARKit或LiDAR。精確測距為支援裝置上的選填增強，有可靠量測才提供；畫面方位不等於真實空間方向，名稱提示不等於碰撞或安全通行判定。ARKit相對位移／轉向可按需要評估，與LiDAR測距分開。以下工具按用途及裝置能力使用，並非全部功能的共同前置。

以下按專案既有基礎及完整目標說明工具分工；延伸模組的具體型號或服務仍可在驗證後調整。

| 工具／技術 | 用途 | 為甚麼使用 |
|---|---|---|
| Flutter／Dart | 介面、任務流程、設定及跨平台共用邏輯 | 讓兩個平台共用主要操作與文案，集中處理無障礙及任務狀態 |
| Swift／Kotlin與平台通道 | 連接iOS／Android原生相機、感測器、語音與地圖 | 需要直接管理硬件、權限及生命週期，保持相機與資料同步 |
| AVFoundation／CameraX | 相機預覽與影像取樣 | 將手機影像交給辨識流程，控制啟停及避免多個任務爭用相機 |
| YOLO／TensorFlow Lite（LiteRT） | 偵測物件，將訓練好的模型放到手機執行 | 以適合手機驗證的偵測流程提供物件框及類別，減少基本辨識對網絡的依賴 |
| ARKit／LiDAR及原生深度能力 | 深度、姿態、物件表面測距及空間資訊 | 單靠二維物件框不能提供可信米數，需要感測器及幾何資料配合 |
| Apple Vision OCR及平台文字辨識 | 菜單、指示牌、樓層文字 | 把圖片文字轉成可搜尋及朗讀的內容，再整理菜名、價格與版面關係 |
| Qwen-VL雲端模型（qwen3-vl-plus） | 按需場景描述，由後端保管Key並作有界請求 | 補充物件清單難以表達的畫面資訊；需網絡及明示上傳，不代即時障礙、路線、樓層、距離或安全通行判定。本機VLM另作後續選型 |
| 系統語音辨識、flutter_tts與讀屏介面 | 語音查詢、粵語／英文播報、VoiceOver／TalkBack操作 | 讓使用者以熟悉的語音及系統無障礙方式完成任務；語音辨識的網絡需求按平台處理 |
| MapKit／Core Location；Android地圖、Places／Location及Routes服務 | 搜尋地點、取得步行路線及更新位置 | 戶外導航需要道路路線及定位資料，與室內深度、場地地圖分開處理 |
| 拓撲地圖與路徑搜尋 | 表達室內路標、連線、樓層及局部候選路徑 | 把「看見甚麼」連接到「目前在哪裏、下一個路標是甚麼」，便於處理封路及場地更新 |
| Firebase Auth、Firestore、Storage、Cloud Functions及App Check | 帳號、私人資料、照片覆核、工作狀態及模型交付 | 統一身分與存取控制，把資料提交、人工覆核及版本管理串成可追溯流程 |
| 本機偏好設定、安全儲存與加密佇列 | 保存語言／語速，保護等待傳送的資料 | 一般設定與敏感資料分開；斷網時可保留工作，恢復後按同意及帳號狀態處理 |
| Python、PyTorch、Ultralytics及資料處理工具 | 整理資料、訓練模型、比較候選與匯出 | 讓改善有固定資料、設定及評估證據，不單靠照片數或訓練輪數判斷 |
| Colab／雲端GPU | 模型研發實驗及訓練運算 | 將較長訓練交給GPU；正式自動服務另需有預算、權限及失敗恢復的worker |
| Git／GitHub、Flutter測試、XCTest及實機測試 | 保存版本、回歸檢查及交付驗證 | 把程式、模型及說明對應到同一版本，保留可追溯及回退的依據 |
