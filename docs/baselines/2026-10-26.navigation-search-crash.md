# iPhone 搜尋閃退修正

## 原因

測試 iPhone 的 2026-10-26 閃退紀錄顯示，主執行緒因 Objective-C 找不到方法而以 SIGABRT 結束，呼叫位置在 Flutter 方法通道分派。原始報告只保留於本機，沒有提交裝置識別資料。

`NavigationPlugin.register` 使用 `addMethodCallDelegate`；Flutter 會呼叫 `handleMethodCall:result:`，對應 Swift 的 `handle(_:result:)`。原有導航實作卻是私有的 `handle(_:_:)`，沒有實作該 Objective-C 接口。註冊委派同時覆蓋初始化時的自訂 handler，因此第一個導航方法即會閃退。搜尋流程先取消舊路線／搜尋，故未開始 MapKit 搜尋便已退出。

修正為 FlutterPlugin 標準接口，並移除重複的方法通道 handler。原生回歸測試檢查 Objective-C selector，透過 FlutterPlugin 委派呼叫取消路線、取消搜尋及搜尋輸入驗證。Flutter 測試使用替身，不能獨自檢查這個原生註冊問題。

## 驗證

- iPhone 模擬器原生回歸：舊實作明確因缺少 `handleMethodCall:result:` 失敗；修正後同一測試通過（1 項，0 失敗）。
- Flutter 全套測試：230 項通過，0 失敗。
- Flutter analyze：0 項問題。
- `git diff --check`：通過。
- iOS 已簽署 Release 建置：通過（沿用本機 Firebase 設定）。
- 已透過 USB 安裝並啟動於測試 iPhone。

手機上的搜尋結果／路線預覽正等待測試者確認，尚未記作通過。戶外定位、語音及完整導航亦未在本次驗收。

本機測試輸出（不提交原始閃退報告）：

- `/private/tmp/pathguide-navigation-selector-red.log`：舊接口缺少 selector 的預期失敗。
- `/private/tmp/pathguide-navigation-selector-green.log`：修正後原生測試通過。
- `/private/tmp/pathguide-search-fix-flutter-tests.log`、`/private/tmp/pathguide-search-fix-analyze.log`。
- `/private/tmp/pathguide-search-fix-ios-release.log`、`/private/tmp/pathguide-search-fix-device-install.log`、`/private/tmp/pathguide-search-fix-device-launch.log`。

## 手機重測

1. 安裝完整原生新版，開啟「路線導航」。
2. 輸入「調景嶺站」並按「搜尋」，確認可顯示結果及地址；重複搜尋五次。
3. 選取結果，允許使用 App 期間的精確定位，確認路線預覽、距離及地圖。
4. 另測沒有結果、斷網及離開導航頁；錯誤應顯示於 App，不應退出。

定位、語音及 HKDI 戶外實走仍按導航驗收清單分開記錄。
