# 領路通 PathGuide 專案背景與現況

現況日期：2026 年 10 月 21 日

領路通 PathGuide 是以香港視障人士為主要服務對象的畢業專題（FYP），希望利用手機相機、人工智能辨識及語音回饋，協助使用者取得周遭環境資訊。目前已實作的核心是裝置端即時物件辨識原型；路線導航及日常生活輔助則是整體構想中的後續方向。本文根據原始 FYP 文件及目前程式碼整理，供導師和組員了解專案背景、實作範圍與下一步工作。

相關設計文件：[無障礙研究與操作設計](ACCESSIBILITY-RESEARCH.zh-HK.md)（2026 年 10 月 22 日），包含研究來源、未來操作規格、文字線框及待執行的驗收清單。

方案已分為 [前端與裝置端](FRONTEND-DESIGN.zh-HK.md)、[Dataset 與模型訓練](DATASET-TRAINING.zh-HK.md)及 [後端與雲端資料流程](BACKEND-DESIGN.zh-HK.md)三份文件；[方案文件索引](INTEGRATED-DESIGN.zh-HK.md)提供分工及閱讀入口。均按設計規格描述，未視為已實作。

帳號專題：[帳號註冊與個人模型流程](ACCOUNT-REGISTRATION.zh-HK.md)補充電話驗證及每人獨立微調模型的後續設計；目前 App 尚未接入這些功能。

## 1. 專案背景與動機

原始 FYP 文件關注視障人士在行路、乘車及餐廳用餐時面對的資訊障礙。即使環境已有無障礙設施，臨時工程圍欄、擺放在通道的物件，以及設施位置或指示資訊，仍可能增加獨立出行的困難。在餐廳內，菜單中的標題、餐點、價格與供應時段亦主要依靠視覺呈現，使用者需要其他方式理解其內容及關係。

本專案的出發點是運用使用者已有的手機，在現有設施之上提供額外資訊。透過相機辨識物件，再把結果轉成語音，讓使用者更容易了解鏡頭所見的環境。專案希望改善出行與生活的自主性；目前的辨識原型仍須透過真機測試及使用者研究，評估它能提供多少實際幫助。

原始構想包含兩條主線：一是出行時的環境與設施辨識，二是點菜或購物時的文字及版面理解。目前開發集中在第一條主線，先建立相機、手機端模型及語音回饋的完整流程。

## 2. 目標使用者與使用情境

主要使用者是香港視障人士。香港場景及粵語互動是本專案的設計重點，因此資料準備著重本地環境，介面使用繁體中文，語音則優先選用香港粵語。

在步行情境中，使用者可把手機鏡頭對準前方，取得行人、單車、垃圾桶、樓梯等物件的辨識提示。在設施辨認情境中，專案希望逐步協助使用者尋找樓梯、扶手電梯等設施；目前提示只反映模型辨識到的類別，尚未結合實際距離、行進方向或可通行路線。

餐廳情境屬後續構想：拍攝菜單後，整理餐點、類別及價格，再讓使用者透過語音查詢及確認。這部分尚未接入目前 App，不能作為現階段可示範的功能。

## 3. 目前 App 的功能

App 使用 Flutter 建立共用介面，底部設有「探索」、「導航」及「設定」三個分頁，啟動時先顯示導航首頁。

### 探索

探索頁已接上 iOS 及 Android 原生相機與內置模型，可顯示即時預覽、物件框及繁體中文標籤。辨識控制面板提供信心門檻、標籤顯示及播報開關，並可查看 FPS、推理耗時及診斷資料。

語音播報優先使用粵語，並按類別優先次序及冷卻時間安排提示，以減少連續畫面造成的重複播報。辨識門檻控制顯示結果，語音門檻控制是否發聲；物件必須同時達到兩個門檻，並符合播報規則，才有機會被讀出。語音門檻會保存在手機。

另外保留三類模擬資料，方便驗證畫框、介面和播報流程。模擬模式可用於演示，但不能證明真實場景的辨識能力。離開探索頁或進入背景時，程式會停止相關相機及播報活動。

### 導航

導航首頁提供「搜尋目的地」、「我的路線」及「錄製新路線」入口，目前均標示為「開發中」。點擊後會顯示功能說明及前往即時辨識的入口，尚未進行地址搜尋、地圖導航、路線儲存或 GPS 軌跡記錄。

### 設定

設定頁可調整三種播報速度，並把選擇保存在手機，也可前往探索頁調整辨識設定。懸空障礙物偵測、碰撞預警、場景描述、導航地圖及方向表達等項目，目前只有未來功能說明。

即時影像在裝置上處理，目前 App 不錄影、不儲存照片或上傳相機畫面。模型隨 App 打包，辨識流程不依賴雲端推理；語音能否離線使用，仍取決於手機實際安裝的語音服務。

## 4. 辨識範圍與技術架構

### 目前九類模型

內置模型是香港九類資料訓練的 YOLO11n，版本為 `2026-10-19.hk9.1`，採用 Float32 TFLite 格式及 640 × 640 輸入。以下按模型輸出次序列出類別；專案 ID 用於對應 App 標籤，與模型內部索引不同。

| 模型類別 | 中文標籤 | 專案 ID |
|---|---|---:|
| bicycle | 單車 | 11 |
| bin | 垃圾桶 | 7 |
| bollard | 護柱 | 8 |
| downstairs | 落樓梯 | 50 |
| escalator | 扶手電梯 | 49 |
| person | 行人 | 6 |
| traffic_cone | 交通錐 | 9 |
| upstairs | 上樓梯 | 51 |
| wet_floor_sign | 小心地滑 | 24 |

扶手電梯類別目前沒有區分運行方向。完整標籤表亦不代表目前模型能辨識表內所有物件，實際範圍以這九類為準。

後續方向判斷會另作動態分析，區分是否有扶手電梯、入口標誌及實際上／下運行；目前的樓梯上／落類別不能用來代替這項功能。使用者操作及手機分析見前端方案，方向資料與評估見 Dataset 方案。

模型清單記錄檔案大小為 10,694,183 bytes，約 10.69 MB。設定頁仍有「2.87 MB」的舊顯示值，本文以現有模型清單為準。

### 裝置端處理與訓練流程

運行流程為：原生相機取得影像 → 圖像前處理 → TFLite 推理與結果解碼 → Flutter 顯示物件框和標籤 → 播報模組選擇提示。iOS 使用 AVFoundation 相機接口，Android 使用 CameraX，辨識結果透過平台通道傳回 Flutter。模型清單提供版本及類別映射，避免把模型輸出解讀成錯誤名稱。

訓練流程則由香港場景資料開始，經標註檢查、資料集切分及格式轉換，在 Colab 微調 YOLO11n，再測試與匯出手機模型。現有準備程式可把多邊形標註轉為偵測框，並檢查完全重複圖片。匯出後一併提供模型與清單，供 App 載入及核對。

依模型文件，來源 PyTorch 模型在獨立測試集的 620 張圖片、964 個物件實例上，mAP50 約為 0.840，mAP50–95 約為 0.568。這些是來源模型的離線評估結果；轉換後的 TFLite 模型尚未重新完成整個測試集評估，不能把上述數字當作手機端準確率或播報成效。

## 5. 原始構想與實作進度

| 功能或方向 | 目前狀態 | 範圍說明 |
|---|---|---|
| 相機及九類物件辨識 | 已實作 | iOS、Android 原生相機與裝置端推理 |
| 中文標籤及語音回饋 | 已實作 | 支援門檻、播報開關、冷卻及語速設定 |
| 模擬資料演示 | 已實作 | 用於驗證介面與流程 |
| 搜尋目的地、我的路線、錄製路線 | 介面預留 | 未接入地圖、GPS 或路線服務 |
| 測距、方向及碰撞預警 | 後續方向 | 未建立可靠的深度、方向與風險判斷流程 |
| 扶手電梯上／下運行方向 | 研究設計 | 需連續影像、同一設備與上下端等證據，尚未實作或驗證 |
| 菜單 OCR、版面理解及語音搜尋 | 後續方向 | 原始文件已有構想，目前 App 未接入 |
| Firebase 登入及照片上傳 | 獨立程式碼，未整合 | 工作區已有相關 Functions 與前端片段，未確認部署及完整流程可用 |
| 電話驗證與個人模型 | 新增設計 | 基本辨識免登入；上傳及私人模型需 UID 認證，尚未實作 |
| 資料回收、再訓練及模型下發 | 後續方向 | 尚未形成由 App 到訓練再回到手機的完整流程 |

原始文件提出收集影像、由 AI 預標註、再經人工修正及持續訓練的方向。現有上傳相關程式碼只是這個方向的一部分，不能據此認定目前 App 已會自動收集照片，或模型更新服務已經運作。

## 6. 現有限制與後續工作

目前版本適合展示從相機到辨識及語音的技術流程。物件框尚未結合實際距離與路線判斷，因此不能直接據此判定碰撞風險或通道是否安全。現有資料亦未提供已完成視障使用者測試的證據。

語音門檻預設為 0.70，沿用自舊模型，尚未針對九類模型重新校準；它不是「七成準確」的意思。新模型的手機延遲、幀率和耗電仍需量度，舊三類模型的效能數字不能直接套用。資料集雖已檢查完全重複圖片，近似圖片及同一影片場景造成的資料洩漏仍未完成評估。

既有驗收文件記錄了靜態檢查、自動測試、Mac iOS 建置及模擬器原生測試結果；這些屬已有紀錄，並非本文重新執行的驗證。iPhone 實際安裝與播報語言、Android 相機真機回歸仍列為待驗收項目。

建議依以下次序推進：

1. 完成九類模型的雙平台真機驗收，記錄裝置、系統、辨識表現、延遲、語音及背景恢復情況。
2. 補充香港場景測試資料，評估轉換後模型，校準各類播報門檻及冷卻規則。
3. 與視障使用者及相關協作者測試操作、提示內容與資訊負擔，據此修訂介面。
4. 根據測試結果發展定位、路線或測距能力；照片上傳功能須先確定用途、同意方式及資料管理流程，再整合後端。
5. 在核心流程穩定後，逐步研究菜單 OCR、版面理解及語音搜尋。
