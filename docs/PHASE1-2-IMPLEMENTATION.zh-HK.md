# 第一及第二階段實作與驗收

日期：2026 年 10 月 22 日。範圍為工程基線、資料契約及現有離線辨識的無障礙流程；九類模型、專案類別字典與原生推理幾何維持現有版本。

## 1 工程及資料基線

改動前 Flutter 3.47.5／Dart 3.13.4 的 107 個測試全部通過。模型清單、實際檔案長度及 SHA256 已核對，記錄於 [工程基線 JSON](baselines/2026-10-22.phase1.json)。自動測試使用模擬平台通道，不能代替相機／語音真機結果。

[資料契約 v1](DATA-CONTRACT.v1.zh-HK.md) 定義 UID、用途同意、照片／預測與人工標註、資料集快照、訓練工作及私人模型授權。雲端欄位是後續實作規格；本輪未建立 Firebase 帳號、部署服務、上傳照片或開始訓練。

[文件待覆核清單](DOCUMENT-AUDIT.zh-HK.md) 已區分保留、更新與清理候選。沒有刪除、移動或歸檔原有文件，三份 Word 及原始資料保持不變。根 README 及 iPhone 文件入口因新行為而更新；歷史數據留待使用者覆核後處理。

## 2 已實作的操作

1. 任務首頁按固定次序提供即時辨識、路線導航、讀取菜單及設定與使用教學；未完成任務在入口標示開發中。
2. 首頁不建立原生相機預覽、不申請相機權限；選擇「即時辨識」即啟動來源及自動播報，首次仍須完成系統相機授權。
3. 主畫面以相機預覽及精簡結果摘要為主；「暫停／繼續辨識」與「更多操作」固定在底部，主操作最少 56 × 56 邏輯像素。重播目前結果、播報開關、門檻、來源及技術資料集中在可捲動面板；不必按重播才能聽到新物件。
4. 暫停、離開辨識頁或進入背景時停止來源及 App TTS，清空框與結果。若中斷前正在辨識，返回前景會自動恢復並提示；手動暫停則按「繼續辨識」才重開。相機授權視窗的短暫 inactive 沿用同一次初始化，避免重複啟動。來源初始化的延遲回應不重新啟動已暫停任務。
5. 預設自動播報，使用者可在更多操作內關閉；開啟系統讀屏不會關閉自動播報。環境結果使用同一輸出層，有讀屏時使用系統無障礙輸出，其他情況使用 TTS。
6. 無系統 announcement 支援時保留可朗讀結果與 live region，不再同時呼叫 TTS。頁面框、FPS 及每幀資料不加入日常讀屏流程；讀取結果時不推移焦點。
7. 讀取結果依現有播報門檻篩選並合併相同類別，模擬模式會說明為模擬結果；無符合結果時顯示「暫未辨識到支援的物件」，超過三秒未更新則提示重試。不推測距離、上落方向或前方安全。
8. 打開更多操作期間停止自動環境播報，關閉後重設播報冷卻，避免補讀面板內積存的結果。使用標準模態路由與關閉按鈕，返回時恢復更多操作按鈕的操作焦點；實際 VoiceOver 焦點仍需真機驗收。
9. 首頁教學可略過，設定可再次開啟；包括持機、標準讀屏手勢、開始／暫停／返回與辨識限制。
10. 設定頁讀取模型清單顯示九類、約 10.69 MB 及實際版本，不再使用舊三類的 2.87 MB。相機權限失敗可重試，未授權時不繼續載入推理模型。

新增類別在上一句完成後可由最新畫面選取，不受五秒全局重複播報冷卻阻擋；每句最多三類，同類至少相隔五秒。沒有結果佇列，不補讀過期畫面。現有門檻、九類模型與類別 ID 不變；目前沒有物件追蹤、可靠距離或行走路徑判斷，不能據此宣稱已完成避障。

## 3 自動檢查與建置

在 `app/` 執行：

```sh
flutter analyze --no-pub
flutter test --no-pub
flutter build ios --debug --no-codesign --no-pub
```

首次環境需先依既有安裝文件執行 `flutter pub get`。無簽署建置不能直接裝到 iPhone。

本輪新增／更新的檢查包括：首頁無相機副作用、進入辨識自動開始、重播結果與模擬識別、權限失敗重試、初始化取消、系統中斷自動恢復、手動暫停保留、權限視窗不重複初始化、設定暫停播報、讀屏開關切換、單一輸出路徑、新類別播報、錯誤分數過濾、模型清單顯示及小螢幕文字放大。首頁及辨識主畫面亦執行觸控範圍、可操作項目標籤及文字對比檢查；不代表所有頁面已通過完整無障礙認證。

2026-10-22 本輪驗證結果：

| 項目 | 結果與範圍 |
|---|---|
| Flutter 靜態檢查 | 沒有問題 |
| Flutter 自動測試 | 127 個全部通過；原始基線 107 個，新增 20 個 |
| 中文畫面預覽 | 390 × 844 任務首頁／精簡辨識頁／更多操作面板；320 × 568、兩倍文字的固定操作及教學對話框，使用模擬框 |
| iOS 無簽署 debug 建置 | Xcode 27.1 通過，產物 `app/build/ios/iphoneos/Runner.app`；不能直接安裝，仍需簽署 |
| 現行模型完整性 | 檔案大小及 SHA256 與原清單一致，模型及類別字典沒有改動 |
| iPhone／Android 真機及視障使用者測試 | 待驗收 |

選擇性本機視覺檢查可用 `PATHGUIDE_SCREENSHOTS` 的 Dart define，測試在 macOS 載入本機中文字體及圖示字體，輸出到指定暫存目錄；預覽使用模擬框，不是 iPhone 相機實測。

## 4 iPhone 真機待驗收

- [ ] 記錄 iPhone 型號、iOS、App 版本、讀屏及語音語言。
- [ ] 首頁及設定不亮相機指示；選即時辨識便開始，首次完成系統授權後不用再按開始或開啟播報。
- [ ] VoiceOver 左右輕掃可按合理次序到標題、狀態及操作；雙擊可暫停、繼續、展開更多操作、重播及返回；辨識結果會自動播報。
- [ ] 用 Screen Curtain 完成以上流程；不把鎖屏或背景當作相機仍運作的要求。
- [ ] 拒絕權限後可理解錯誤、前往系統設定修正、重試或返回；錯誤不自動要求另一種權限。
- [ ] VoiceOver／TalkBack 環境結果不與 App TTS 重複；手動結果、開關自動播報及進入設定沒有互相搶聲。系統已接收的 announcement 能否中止需按裝置測試，不能保證 App 能撤回。
- [ ] 沒有粵語、TTS 初始化失敗、播報中途暫停／離頁及來電後均可恢復操作，不保留舊語音工作。
- [ ] 來電、切 App、鎖屏後返回，原本正在辨識的任務自動恢復並提示；手動暫停不自動恢復。權限視窗及重試不建立兩個相機工作。
- [ ] 系統大字體、放大及直向小螢幕可操作；主按鈕不需拖曳或長按。
- [ ] 重新量度九類模型的延遲、幀率、耗電及裝置溫度；不沿用舊三類模型數據。
- [ ] 安排包含全盲／低視能及不同讀屏經驗的香港使用者試用，記錄理解、完成、求助及誤操作；尚未宣稱已完成測試。

## 5 後續邊界

Google／Apple／短訊登入、照片收集與上傳、私人訓練及下載仍屬第三階段以後。圖示模型、OCR、導航、菜單分析、扶手電梯方向、主題選擇及震動偏好亦未在本輪接入。連續播報預設開啟，與讀屏的語音協調仍須通過真機驗收。

參考：[Flutter 無障礙測試](https://docs.flutter.dev/ui/accessibility/accessibility-testing)、[Flutter 系統 announcement API](https://api.flutter.dev/flutter/semantics/SemanticsService/sendAnnouncement.html)。系統 API 與目前 SDK 實作一併核對，不把模擬測試當成真實讀屏結果。
