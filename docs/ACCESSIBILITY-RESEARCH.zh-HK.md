# 領路通 PathGuide 無障礙研究與操作設計

研究檢閱及設計日期：2026 年 10 月 22 日

領路通應讓視障使用者透過讀屏、固定位置的按鈕及清楚的狀態回饋，完成辨識、導航及讀取菜單的任務。語音輸入用於有需要的搜尋與查詢，所有核心操作亦須能透過按鈕完成。

本文供導師、組員及後續開發者使用，整合公開指引、同類 App 的使用方式與目前程式碼，提供操作規格、文字線框及驗收清單。本次交付是研究與設計文件，尚未修改 App、建立可操作原型、完成真機無障礙審核或招募使用者測試。

工程方案分別記錄於 [前端與裝置端方案](FRONTEND-DESIGN.zh-HK.md)、[Dataset 與模型訓練方案](DATASET-TRAINING.zh-HK.md)及 [後端方案](BACKEND-DESIGN.zh-HK.md)；[方案文件索引](INTEGRATED-DESIGN.zh-HK.md)提供閱讀入口。本文保留完整的無障礙研究、任務線框及操作要求。

## 1. 設計範圍與證據分類

已確認的方向為：整個 App 的長遠體驗、iPhone 優先、先選任務再明確開始，以及讀屏與按鈕為主、按需語音輸入。Android 保留相同任務結構，另外驗證 TalkBack 的操作差異。

本文使用以下分類，避免把建議當作已完成的成果：

| 分類 | 意義 |
|---|---|
| 研究事實 | 公開來源直接支持的使用方式或功能，不代表所有視障人士的習慣 |
| 程式現況 | 從本地程式碼確認的行為，不等於已通過真機讀屏驗收 |
| 設計規格 | 本專案選定的目標行為，需後續實作與驗收 |
| 待驗證假設 | 尚待真機、使用者或技術原型測試的判斷 |

本輪不決定地圖服務、定位方案、OCR 模型或語音辨識後端，也不新增 API、資料庫欄位或系統權限。未完成的導航、錄製路線及菜單功能均按未來原型描述。

## 2. 研究事實與設計啟示

### 2.1 視障人士如何操作手機

VoiceOver 允許使用者觸摸探索，或逐項移動焦點，再雙擊啟動目前項目；雙擊毋須落在原按鈕的位置。TalkBack 同樣提供觸摸探索與焦點操作，但部分手勢可隨版本及設定改變，Android 教學須按實際裝置驗證。[Apple VoiceOver 手勢說明](https://support.apple.com/en-au/guide/iphone/iph3e2e2281/ios)、[Google TalkBack 操作說明](https://support.google.com/accessibility/android/answer/6006598?hl=en)

全盲與低視能使用者可能採用不同組合的輔助功能。RNIB 及香港失明人協進會介紹的方式包括讀屏、放大、文字大小與顏色調整；不能只憑「有語音」便判斷介面容易使用。[RNIB App 指引](https://media.rnib.org.uk/documents/App_Guidelines.pdf)、[香港失明人協進會手機輔助功能介紹](https://www.hkbu.org.hk/uploads/files/EOC_Sep2016.html)

| 使用方式 | 領路通的設計啟示 |
|---|---|
| 逐項聽取介面 | 每個項目需有可理解的名稱、角色及狀態，次序須符合任務 |
| 觸摸探索 | 常用操作位置穩定，按鈕有足夠觸控範圍 |
| 放大及大字體 | 放大後內容可重排，不能把主要按鈕擠出可操作區域 |
| 語音輸入 | 使用者可開始、停止、覆核及修改，不要求持續開咪高峰 |
| 相機輔助 | 要說明持機方式、處理狀態及失敗後的下一步 |

以上是設計推論，不是對香港視障人士手機使用比例的調查。讀屏熟練程度、出行習慣及聽覺需要，須在後續訪談確認。

### 2.2 同類 App 的可借鏡之處

| 參考產品 | 來源描述的行為 | 領路通採用的方向 |
|---|---|---|
| Seeing AI | 文件拍攝有聲音引導，結果可按任務取得 | 把拍攝引導納入流程，結果先提供重點 |
| Be My AI | 可追問、補拍，並處理取景或對焦不足 | 提供明確重試，不假設一次拍攝即可完成 |
| NaviLens | 可調整語音、聲音、震動與資訊篩選 | 提供可選回饋，控制資訊量 |

Seeing AI 以上行為見於 Microsoft 的 2023 年官方介紹，本文借鏡其互動方法，不以舊文章代表最新完整功能。[Microsoft Seeing AI 介紹](https://blogs.microsoft.com/accessibility/seeing-ai-app-launches-on-android-including-new-and-updated-features-and-new-languages/)

Be My AI 的官方說明包含追加圖片、追問及取景不足時重拍的流程。[Be My AI 使用說明](https://support.bemyeyes.com/hc/en-us/articles/18133134809105-Using-Be-My-AI)

NaviLens 依靠專用光學標記提供資訊，其偵測距離與方向能力不能直接套用至領路通的九類物件模型。[RNIB NaviLens 介紹](https://www.rnib.org.uk/living-with-sight-loss/assistive-aids-and-technology/navigation-and-communication/navilens/)

## 4. 共通操作規格

### 4.1 首頁與首次教學

首頁固定依次提供「即時辨識」「路線導航」「讀取菜單」「設定與使用教學」。未完成的入口在名稱及讀屏狀態中標示「開發中」；可開啟簡短說明，但不能啟動模擬結果冒充真實服務。

帳號流程見 [帳號註冊與個人模型流程](ACCOUNT-REGISTRATION.zh-HK.md)：基本離線辨識免登入，上傳及私人模型前以短訊驗證碼登入；使用單一驗證碼欄，支援讀屏、貼上及自動填入。註冊不代表已同意照片收集。

首次教學可跳過，完成或跳過後到首頁，之後可從設定重播。教學包括讀屏操作提示、後置鏡頭位置、開始與暫停，以及如何返回。iPhone 教學使用 VoiceOver 慣例，不要求關閉讀屏，也不要求申報是否失明。

首頁不啟動相機、定位或錄音。選擇即時辨識後，先提供持機說明及「開始辨識」；首次開始時才解釋並申請相機權限。定位及咪高峰亦只在相應功能需要時申請，拒絕後仍可返回及使用其他可用任務。

### 4.2 語意與焦點

每頁朗讀次序固定為「頁面標題 → 任務狀態 → 主要操作 → 結果 → 其他設定」。標題具標題角色，按鈕具名稱及可用狀態，切換項具目前值；例如由讀屏組合朗讀「自動播報，關閉」。避免把「按鈕」重複寫入名稱。

動態畫框、裝飾圖示及 FPS 不進入日常焦點次序；技術資料保留在可主動開啟的進階區域。結果使用穩定的文字摘要，畫面更新不主動移動焦點，也不把每幀結果設為自動朗讀區域。

開啟新頁時讓使用者知道頁名；開面板時焦點進入其標題，面板期間不遍歷背後內容，關閉後回到原按鈕。權限對話框結束後回到原任務的狀態或重試操作。所有離開方式均有可讀的返回／關閉按鈕，不只依賴拖曳、點背景或手勢。

### 4.3 狀態與錯誤

| 狀態 | 顯示與回饋例句 | 可用操作 |
|---|---|---|
| 尚未開始 | 「即時辨識尚未開始」 | 開始、使用說明、返回 |
| 準備中 | 「正在準備相機與模型」 | 取消、返回 |
| 辨識中 | 「辨識中」 | 暫停、讀取目前結果、自動播報、設定、返回 |
| 已暫停 | 「辨識已暫停」 | 繼續、返回 |
| 權限拒絕 | 「未能使用相機。可到系統設定允許，或返回首頁」 | 前往設定、重新檢查、返回 |
| 初始化失敗 | 「辨識暫時不可用，請重試」 | 重試、錯誤詳情、返回 |
| 語音不可用 | 「語音暫時不可用，仍可查看文字結果」 | 重試語音、文字結果、返回 |

狀態改變只通知必要資訊一次。錯誤先說明影響及下一步，完整技術錯誤放在詳情內；若需複製，提供明確「複製錯誤詳情」按鈕。

### 4.4 語音輸出與錄音

| 情況 | 設計規格 |
|---|---|
| VoiceOver／TalkBack 已開啟且沒有儲存偏好 | 預設按需讀取結果，連續播報由使用者啟用 |
| 讀屏未開啟且沒有儲存偏好 | 明確開始辨識後可自動播報，主畫面提供關閉操作 |
| 使用者已選擇播報方式 | 保存偏好；進入任務時提供可讀狀態，不默默改變 |
| 讀取目前結果 | 讀取當前任務最新有效摘要，不重播舊任務或歷史紀錄 |
| 開啟設定或開始錄音 | 暫停自動物件播報，關閉或結束後按原設定恢復 |
| 暫停、返回或結束任務 | 停止任務語音並清除待播結果，不影響系統讀屏 |

VoiceOver 負責介面朗讀；環境結果經統一播報層選擇系統無障礙通知或 App TTS，同一內容只走一條輸出路徑。不得同時由語意自動通知與 `flutter_tts` 重複讀取。普通物件提示不能反覆打斷使用者探索按鈕，過期結果直接丟棄。

實作時須用真機原型驗證讀屏與 TTS 的先後次序、取消及音訊中斷。若連續播報未能穩定協調，讀屏模式保留按需結果，不開放該模式的連續播報。這是驗收條件，尚未證實現有音訊設定可達成。

語音輸入只在使用者按「語音輸入」後開始，提供「停止錄音」與「取消」。錄音前停止 App 播報，結束後顯示及讀出辨識文字，使用者可修改或確認；空白及失敗結果不直接執行。文字鍵盤輸入始終可用。

### 4.5 低視能、聲音與震動

主要操作的觸控範圍至少為 56 × 56 Flutter 邏輯像素；這是本專案的設計目標，不是引用為所有平台的最低標準。小螢幕或最大文字設定下，按鈕可改為直向排列，內容可捲動，主要操作不與系統安全區重疊。

保留相機預覽、物件框與中文文字，提供跟隨系統、淺色及深色主題，避免單靠紅綠色表達狀態。開始、暫停及失敗可提供可關閉的短震動，並同時顯示可讀狀態。震動只輔助確認，不表示障礙物距離或保證安全。

「簡短／詳細結果」「震動開關」及明暗偏好放在一般設定；模型門檻、FPS、模擬資料與診斷放在進階設定。第一版不要求使用者調整模型信心數字，預設門檻仍需另作校準。

## 5. 核心流程與文字線框

以下線框均為設計稿，方括號表示控制項，不是目前 App 的截圖。導航、路線及菜單的示例資料不能作為真實測試結果。

### 5.1 任務首頁

```text
領路通                                      頁面標題
選擇需要的協助

[即時辨識]
[路線導航 — 開發中]
[讀取菜單 — 開發中]
[設定與使用教學]
```

正式開放功能時才移除「開發中」。首頁不放自動輪播、動態播報結果或要求滑動才能發現的主要任務。

### 5.2 即時辨識

流程：首頁 → 持機說明 → 開始辨識 → 準備／辨識中 → 讀取結果 → 暫停／繼續／返回。

```text
即時辨識                                    頁面標題
辨識中                                      任務狀態

[暫停辨識]                                  固定主操作
[讀取目前結果]
[自動播報：關閉]

目前結果                                    穩定摘要區
行人、垃圾桶                                僅為示例
相機預覽與物件框                            保留視覺資訊

[辨識設定] [使用說明] [返回首頁]
```

開始前提示「請直向持機，後置鏡頭朝向你想了解的環境，避免手指遮住鏡頭」。這是持機說明，不代表系統已能判斷鏡頭是否遮擋。

「暫停辨識」停止相機分析與 App 播報，清除即時結果，按鈕變為「繼續辨識」。返回首頁結束任務。背景及鎖屏時暫停；回到前台先呈現「已暫停」，由使用者明確繼續。這是新規格，與目前前台恢復後重新啟動來源的程式行為不同。

摘要只使用目前有效的九類結果，按既有類別優先級排序、同類合併，不宣稱精確人數或距離。沒有達門檻的物件時讀出「暫未辨識到支援的物件」；沒有有效新影像時則說「暫時沒有可用結果，請重新辨識」，不能把相機停頓誤當作沒有物件。

目前只有物件框資料，不提供「前面安全」「可以前進」、公尺距離或鐘點避障指令。辨識誤差、鏡頭視野及支援類別範圍仍存在，樓梯等提示也不能當作已驗證的碰撞預警。

「查詢扶手電梯方向」屬新增研究設計，需另外分析入口標誌、同一設備、上下端及連續影像；未實作前標示「開發中」，只有扶手電梯框時回覆「暫時未能判斷上落方向」。操作及裝置端分析見前端方案第 3 節，方向短片與評估見 Dataset 方案第 4、5 節。

### 5.3 路線導航與錄製路線

導航流程：目的地 → 地址及路線摘要覆核 → 明確開始 → 重播／查詢位置／暫停 → 確認結束。目的地入口依次提供最近使用、我的路線及搜尋；搜尋同時支援文字與按需錄音。

```text
確認目的地
目的地名稱、完整地址及路線摘要               由使用者覆核
[開始導航] [修改目的地] [返回]

導航中                                      未來原型頁面
下一步指示、定位狀態                         由定位服務支持
[重播下一步] [目前位置]
[暫停導航] [結束導航]
```

開始前覆核同名地點及地址，未定位或無法取得路線時不進入「導航中」。定位不足時告知「定位暫時不足，無法提供下一步」，暫停精確轉向提示；重新取得位置後更新狀態。偏離路線須基於定位證據，不能從物件框推論。

「結束導航」先開啟「繼續導航／確認結束」對話框，焦點先到繼續；確認後回到導航入口。「暫停」停止導航提示，保留任務供繼續，不刪除路線。

錄製路線放在「我的路線」內：開始錄製 → 加入路標 → 暫停／繼續 → 完成 → 命名及覆核 → 儲存。錄音路標以按鈕開始和結束，亦可輸入文字；返回時若有未儲存資料，提供繼續編輯或放棄。沒有定位或路線服務的原型必須標示模擬，不能聲稱已記錄真實軌跡。

導航提供額外位置及路線資訊，不能取代白杖、導盲犬或使用者的定向行動技能；RNIB 亦指出 GPS 有局限。[RNIB GPS 導航指引](https://www.rnib.org.uk/living-with-sight-loss/assistive-aids-and-technology/navigation-and-communication/what-is-gps-navigation/)

### 5.4 讀取菜單

流程：開始拍攝 → 拍攝引導 → 拍照 → 分析 → 類別 → 餐點／搜尋結果 → 重讀／修正搜尋／重拍。

```text
讀取菜單
準備拍攝
[拍照] [拍攝說明] [返回]

菜單結果                                    未來原型頁面
辨識到的類別：午餐、下午茶、飲品              僅為示例
[午餐] [下午茶] [飲品]
[文字搜尋] [語音搜尋]
[重新拍攝] [返回]

餐點詳情
餐點名稱、價格、可確認的選項
[重讀] [返回類別] [修改搜尋]
```

拍攝時只在品質分析有依據時提示偏離、模糊或光線不足；未實作該分析前只提供一般說明，不假裝已判斷取景方向。拍照後告知正在分析，提供取消；失敗時可重試或重拍。若分析需上傳，拍攝前清楚說明，取得同意後才上傳。

結果先讀出實際辨識到的類別，不自動讀完整張菜單。未辨識到類別時提供逐項清單及重拍，不虛構分類。價格或選項不清楚時標示「未能辨識」，搜尋無結果則提供修改或重拍；語音辨識文字須先覆核。此流程只輔助閱讀與選擇，不代表已向餐廳下單。

## 6. 實作次序與驗收清單

### 6.1 分階段交付

第一階段實作現有辨識流程的任務首頁、明確開始與暫停、固定操作、語意、焦點及語音協調。完成 iPhone 真機驗收後，再製作導航、錄製路線及菜單的可操作原型，依使用者回饋修訂，再另行決定後端整合。

目前的 [專案現況說明](PROJECT-OVERVIEW.zh-HK.md)及 [既有 iPhone 驗收文件](IOS-DEMO.md)描述已實作版本；本文件的目標行為不能反寫為已完成現況。

### 6.2 自動與靜態檢查

Flutter 官方提供觸控大小、標籤及文字對比的測試接口，以及 Accessibility Inspector 檢視方法。這些檢查不能取代完整的讀屏操作測試。[Flutter 無障礙測試指引](https://docs.flutter.dev/ui/accessibility/accessibility-testing)

- [ ] 語意樹中，主要按鈕各只有一個可啟動節點，名稱、角色及開關狀態正確。
- [ ] 首頁至開始辨識前不初始化相機，不要求定位或咪高峰權限。
- [ ] 狀態轉換、取消及返回會停止舊任務，不播出上一個任務的結果。
- [ ] 開關讀屏、開面板及錄音的語音策略符合第 4 節，沒有重複輸出路徑。
- [ ] 通過 `iOSTapTargetGuideline`、`androidTapTargetGuideline`、`labeledTapTargetGuideline` 及 `textContrastGuideline`，另驗證主操作的 56 × 56 專案目標。
- [ ] 小螢幕、最大系統文字、明暗主題及長中文內容下無截字或不可達按鈕。

### 6.3 iPhone 真機與非視覺操作

每次記錄 App 版本、iPhone 型號、iOS、讀屏語言、聲音輸出方式及結果。使用 Screen Curtain 檢查非視覺操作；Screen Curtain 隱藏畫面但手機仍可操作，與鎖屏不同。[Apple Screen Curtain 說明](https://support.apple.com/guide/iphone/keep-the-screen-off-iph756788a12/ios)、[Apple VoiceOver 支援與測試建議](https://developer.apple.com/documentation/uikit/supporting-voiceover-in-your-app?changes=_7_9&language=objc)

- [ ] VoiceOver 開啟時可完成教學、首頁選擇、開始、讀取結果、暫停、繼續及返回，毋須健視者指出按鈕位置。
- [ ] 狀態改變可理解，物件框持續更新不搶焦點；開關面板後焦點位置正確。
- [ ] 可用明確按鈕關閉所有面板，沒有必須拖動或長按才能完成的核心步驟。
- [ ] 有結果、無達標結果、影像中斷及模型失敗的提示互不混淆。
- [ ] 觸摸探索按鈕時不被普通物件語音持續蓋過；自動播報不能穩定協調時保留按需模式。
- [ ] 相機拒絕、語音服務不可用、耳機切換及來電後仍可理解狀態並恢復操作。
- [ ] 鎖屏或切到背景後任務暫停，返回前台須明確繼續；Screen Curtain 不被誤當成鎖屏。
- [ ] 讀屏關閉後仍可使用大字體及視覺操作，震動關閉後仍能知道任務狀態。

Android 階段重跑相同任務，以 TalkBack 實測焦點、調整控制及音訊，不直接複製 iPhone 手勢教學。

### 6.4 使用者測試與原型情境

首輪規劃約五名香港使用者，包含全盲、低視能及不同 VoiceOver 熟練程度；實際組成須記錄，這是探索性測試，不推算整體滿意度。先取得參與同意，記錄既有手機操作習慣與所用輔助功能，不要求停用日常輔助工具。

| 測試任務 | 觀察及記錄 |
|---|---|
| 不看畫面開始辨識並取得結果 | 完成情況、步驟、求助次數、提示是否清楚 |
| 暫停、設定語速、返回再繼續 | 誤觸、焦點遺失、對目前狀態的理解 |
| 拒絕權限或遇到無結果 | 能否說出原因及自行找到下一步 |
| 覆核同名目的地、定位不足、結束導航 | 原型中能否修改目的地及理解不確定狀態 |
| 錄製路線後覆核或放棄 | 是否理解錄製、暫停與已儲存的差別 |
| 菜單重拍、搜尋錯誤、返回類別 | 是否能修改問題，理解未知價格並恢復瀏覽 |

即時辨識先在受控、靜止情境測試；導航與菜單先使用明示為模擬的原型，不把原型測試當作實地導航能力證明。完成時間只作診斷，不鼓勵為快而忽略確認。

第一階段通過條件為核心辨識任務沒有阻止獨立完成的已知問題，且語音、焦點及錯誤恢復清單通過；使用者測試發現的阻塞問題須修正後重測。未招募到使用者時可先完成工程測試，但須標記「使用者驗證未完成」。
