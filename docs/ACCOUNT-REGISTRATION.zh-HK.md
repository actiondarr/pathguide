# 領路通帳號及緊急聯絡人

更新日期：2026 年 10 月 23 日。第三階段改為 Google 登入優先，電話短訊及 Apple 登入延後。本輪程式已接入 Google／Firebase SDK，但真實專案設定及真機驗收待完成；詳細交接見 [第三階段實作](PHASE3-IMPLEMENTATION.zh-HK.md)。

## 1 使用流程

訪客直接使用內置模型辨識。首頁、設定及辨識頁「更多操作」提供帳號入口；進入帳號頁會釋放辨識頁的相機及 App 播報，返回辨識任務時依現有流程重新開始。

登入前閱讀帳號用途說明並確認，選擇「使用 Google 登入」。Google／Firebase 完成驗證後，以 Firebase UID 讀取或建立帳號；不要求電話、密碼、生日或緊急聯絡人。取消或網絡錯誤不影響訪客辨識。

首次建立後可選填一位緊急聯絡人，亦可選「稍後設定」返回原任務。帳號初始化失敗時保留已驗證身分並提供重試，不重新建立另一個 UID。Firebase 未配置時顯示原因，不提供假登入或測試身份。

## 2 資料及權限

| 資料 | 保存及用途 |
|---|---|
| 登入身分 | Firebase Auth SDK 管理；使用 UID，不以電郵或顯示名稱作擁有者 |
| 帳號記錄 | `users/{uid}`；schemaVersion 1、active 狀態、用途版本及伺服器時間 |
| 緊急聯絡人 | `users/{uid}/private/emergencyContact`，獨立於照片及訓練資料 |
| 本機聯絡副本 | 系統安全儲存，含 ownerUid；只供同帳號離線讀取，登出或刪除時清除 |
| 刪除保護 | `account_deletions/{uid}`，只含 schemaVersion 及伺服器時間；不保存姓名、電話或電郵 |

第三階段使用 Authentication／Firestore；無需先部署 Cloud Functions。Security Rules 驗證 token 的 UID 及 Google provider，限制本人資料，拒絕客戶端自行提升角色、修改帳號狀態、加入任意欄位或存取他人資料。Firestore 磁碟持久快取關閉，私人離線副本另由安全儲存處理。

目前沒有照片收集或私人模型下載。登入不等於取得訓練同意，亦不會自動擷取、上傳或訓練。照片用途同意仍沿用獨立契約，於第四階段接入，缺少同意視為未開啟。

## 3 緊急聯絡人

稱呼為一至六十字，電話須有效，關係最多三十字並可留空。香港八位數號碼會標準化為 +852；其他地區使用完整國際號碼。第一版只保存一位聯絡人，可新增、修改及刪除。

首頁及「更多操作」可找到聯絡按鈕，讀屏名稱包含稱呼及電話。只有使用者啟動才交由系統撥號；App 顯示「已交由系統處理撥號」，不宣稱已接通或成功求助。無法啟動撥號時提示使用電話 App。沒有自動事故判斷、位置分享、短訊或通訊錄讀取。

請先取得聯絡人同意。這些資料不加入照片、標註、訓練匯出或個人模型；照片覆核人員不因此取得聯絡資料權限。

## 4 登出 切換及刪除

Firebase SDK 恢復同一帳號身分。離線時只可讀取同一已恢復 UID 的安全聯絡副本；不把離線快取當成新的雲端授權。帳號變更立即清空畫面，延遲讀取或儲存不得寫進新帳號的畫面及快取。

登出清除本機帳號資料及安全副本，回到訪客。刪除帳號先確認，再重新驗證同一 Google 身分；建立不可由客戶端移除的刪除保護、清除本階段 profile 及聯絡資料，再移除 Firebase Auth 身分。若最後一步失敗，保留「刪除待完成」及重試，不重新初始化舊 UID。

刪除保護只用於阻止延遲操作重建已刪資料，後續保留及清理由後端管理。第四階段開放照片前必須擴充完整後端刪除工作，涵蓋照片、匯出及訓練產物，不能沿用第三階段的有限清理。

## 5 後續登入方式

電話短訊及 Apple 登入列於第七階段；日後以明確的帳號連結流程保留原 UID，不根據相同電郵自動合併兩個帳號。準備公開上架時另核對 Apple 對登入方式的要求。
